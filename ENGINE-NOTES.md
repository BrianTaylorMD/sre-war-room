# Engine notes (handoff from the engine build, 2026-10-06)

ANALYSIS API: WR.analyze(input) -> Analysis (SPEC 4). Pure, synchronous, never throws: every stage is wrapped and failures become warnings; on an unexpected throw it returns a complete empty skeleton. Optional input.generatedAt (epoch ms) pins generatedAt; otherwise generatedAt = window.now when known, else Date.now(). Helpers: WR.analyze.isError(sig), WR.analyze.isAnomaly(sig), WR.analyze.scanCerts(logsText, ctx, alertSignals), WR.analyze.detectHandoffs(signals), WR.analyze.MAX_SIGNALS = 3000.
- Pipeline: clean the context (defaultTz, now, year, deployedAt, cluster, slo) -> parse alerts, traces and helm, then logs (the year comes from those panes when the context gives none) -> now = context.now, else the latest logs/traces/alerts time -> WR.time.rebase -> reconcile entities and remap ids in signals, changes, deploys, trace edges, log dependency hints, componentCounts and the alert burn -> give node OOM-killer lines back to the workload they name -> edges -> first anomaly and window -> statuses (failing, degraded, at-risk, deepest) -> deploy time (Helm, else a ReplicaSet hand-off) -> hypotheses -> root -> impact and statusSince -> clusters -> budget -> rollbacks -> severity and headline -> timeline -> signal cap -> traits -> warnings.
- WR.budget(slo, {errorRatio, errorRatioSource, firstAnomaly, now, note}) -> Budget (SPEC shape plus budgetSpentBeforePct and notes[]). Also WR.budget.normalizeSlo(slo) -> {target, windowDays, requestsPerMin, budgetSpentBeforePct, errorRatioOverride, warnings}: accepts 99.9 as a percent and guards bad values. WR.budget.resolveErrorRatio(slo, {alertBurn, traceStats, requests}) -> {errorRatio, source, note}, priority override > alert (errorRatio, or burnRate x (1 - SLO)) > traces entryErrorRatio > logs 5xx share (at least 20 request lines) > default 0.01. Also WR.budget.consumedPct(burn, minutes, windowDays), WR.budget.alertRows(windowDays, burn, incidentMinutes), WR.budget.savedPct(budget, etaMinutes, effect), WR.budget.round, WR.budget.SOURCE, WR.budget.DEFAULT_ERROR_RATIO.
- WR.hypotheses(hctx) -> Hypothesis[] (6 at most; 3 at most per component), sorted by confidence, then raw score, then category specificity, then id. Scoring: 1 - product(1 - w); x1.15 when the anchor (deploy time or certificate Not After) comes 0-60 min before the component's first error; x0.6 when errors started more than 1 min before an anchoring change; x1.1 for the deepest failing node; capped at 0.95; held at 0.5 when there are fewer than 2 evidence items. REVIEWER GAPS (known, not yours to fix unless trivial): `kubectl get events -o yaml` and `kubectl get pods -o json` are not parsed.
- helm-diff dyff, template and json output modes are not parsed.
- A double rollback is not handled: when the latest history row is 'Rollback to <the bad revision>', the correct rollback is suppressed.
- In the Helm pane, a JSON body inside a ConfigMap diff can be read as a fake JSON segment and hide a later `-o json` document.
- The trace database name ('orders') is still a separate component from 'orders-postgresql'.
- CoreDNS created from traces has no graph edges.
- Wrong-pane pastes are only warned about, never re-routed.
- A release that was rolled back and kept failing gets traffic-shift as its recommendation; that recommendation is not well tested.
- Helm-only pastes still offer a low-confidence rollback at SEV4.
- Reading amtool extended tables and Slack/subject text is heuristic. amtool with a custom --date.format is not read. A subject like '<alert> for job <svc>' can still take 'job' as a namespace.
- `firing` on budget alert rows is still optimistic. The 1-hour row shows firing at about 22 minutes, while Workbook detection time is about 53 minutes; firesAfterMinutes and the note explain this, but the UI must show them.
